Build Book

The other docs explain how each system works. This one is the operator's manual: what to click, in what order, for the jobs that come up while making content. Every entry points back at the deep doc when there is one.

Front end & boot order

New since the last edition: the title screen and the garage sheet are real scenes and the menu now leads somewhere.

#SceneWhy it's in the list
0Assets/Scenes/DemoMenu.unityStill the boot scene — the new screens were appended, not slotted in front
1Assets/Scenes/WatkinsGlen.unityThe hand-authored reference road course
2Assets/Scenes/RaceScene.unityThe shared race scene every track package loads into
3Assets/Scenes/TitleScreen.unityFront-end menu
4Assets/Scenes/GarageScreen.unityGarage character sheet

What each title row does

  • NEW SEASON — fresh weekend at newSeasonTrackId, which defaults to TrackCatalog.DefaultTrackId = WatkinsGlen. It is pinned rather than "wherever the calendar starts" because Watkins Glen is the one track with both a layout and a content package.
  • CONTINUE — back into the selected track as it stands, falling through the same has-geometry check (the travel map can leave TrackSelection on a catalogue-only track).
  • EXHIBITION — one race, no practice or qualifying.
  • GARAGE — loads GarageScreen; its BACK returns here and its RACE button goes to RaceScene.
  • OPTIONS — NotWired, drawn disabled on purpose.

Keys: arrows / WS to move, Enter / Space / E to confirm, d-pad and south button on a gamepad.

A row whose destination isn't in the build settings draws disabled, so a half-wired menu reads as half-wired instead of dead. If a row you just wired is greyed out, the scene isn't in the list.

Rebuilding either screen

Both are the authored-canvas pattern: a builder writes the layout into the scene once, and a thin binder (TitleScreenUI / GarageScreenUI) fills it. Re-running Build Title Screen Scene or Build Garage Screen Scene rewrites the layout and the wiring, so a rebuild never leaves the menu pointing at nothing — but it does drop hand edits to the canvas.

The garage sheet binds to what the game really keeps: the player's row in the Drivers table via PlayerDriver, fan appeal as the XP meter, PlayerStatsLedger for career and accolades, the VehicleInfo with fitted parts applied for the car numbers.

Screen-by-screen spec: Docs/IronOvalKit.md §Title screen, §Garage screen

Tracks

One string id — Daytona — resolves to a catalogue row, geometry, and a content package. The shared race scene loads the package.

Add a new oval

  1. Check it is in the calendar: Assets/Scripts/Database/DummyTracks.cs. Most of the 35 are already there with type, length, banking and laps. If you edit that seed, bump DatabaseManager.SchemaVersion so the table rebuilds.
  2. Draftmaster›Tracks›Track Builder Window. Find the row, press Generate Layout — writes Resources/Tracks/<id>.asset. Regenerating refills the asset in place, so its GUID (and every reference to it) survives.
  3. Build Package — writes Resources/TrackPackages/<id>.prefab and dresses it. What comes out is drivable and walkable without opening it.
  4. Race — sets TrackSelection; open RaceScene and press Play.

Tracks›Report Calendar Coverage prints what's built vs catalogue-only. Dress All Undressed Packages fills in every package missing scenery. Detail: Docs/Tracks.md

Add a road course

The generator refuses road courses — there is no formula for one. Duplicate Assets/Resources/Tracks/WatkinsGlen.asset, rename it <id>.asset, edit its segment list (Straight/Turn with length, angle, banking, width, plus the racing-line offsets), then Build Package from the Track Builder Window as above.

Change a track's scenery

Open the package: Draftmaster›Tracks›Edit Selected Package (Prefab Mode), or In Context (Race Scene) to see it against the managers. Move, delete or replace anything.

Re-dressing (Dress Selected Package) only ever replaces pieces it generated — those inside the Environment / Paddock roots, or carrying its names. Hand-made pieces are kept and reported. Kerbs, garages, signage and camera towers are hand work by design.

Paint the start/finish or pit-exit line

Strip arrays can't be grown through the MCP property API, so these are menu items:

  • Tools›Track›Add Missing Finish Line Strips — anchors a strip to TrackInfoV2.startFinishDistance.
  • Tools›Track›Add Missing Pit Exit Lines — anchors to PitExitLineDistance, where the pit limiter releases.
  • Tools›Track›Rebuild Track Environment after either.

See the pit boxes while authoring

Draftmaster›Debug›Show Pit Boxes (a checked toggle) draws the box ladder at edit time from the same PitLane.FitBoxes call the spawner makes — so it is where cars and crews actually end up. Log Pit Box Lines dumps distances and local positions for placing the painted dividers; Log Pit Fit explains a "field doesn't fit" layout.

People

Markers, not prefabs: the body is cloned from the on-foot prefab at runtime and the dialogue components are attached to it.

Place an NPC

  1. Decide where the marker lives: track-specific → the package, under Paddock/NPCs; every track → RaceScene.unity.
  2. Empty GameObject + PlacedNPC, or Draftmaster›NPCs›Add Placed NPC — drops one at the scene-view pivot, parented correctly when a package is open in Prefab Mode.
  3. Set the anchor: Here inside a package, otherwise a geometry anchor (PitLane, ParkedCar, RVDoor, PlayerSpawn) so one marker works at all 35 tracks. ParkedCar needs followAnchor on — the car is re-parked into its fitted box a few frames after the scene opens.
  4. Set the interaction: TalkOnInteract / WalkUpCutscene / OnCarEntry / Silent, plus lines.
  5. Gate it with AppearanceConditions — session, series, track, career stats, quest state, inventory, career path, repeat scope, chance.

Geometry anchors only resolve with a track loaded. In the race scene run Tracks›Preview Selected Package In Scene first, then Clear Package Previews From Scene when done — otherwise the gizmo is lying to you.

Marker in the wrong file? Draftmaster›NPCs›Move Selected NPC Into Track Package moves the selected marker into Paddock/NPCs of the selected track's package, copying the component wholesale (CopySerialized) so the tuned anchor, trigger ring, dialogue and appearance conditions all survive the trip. Add RV Engineer To Open Package drops a fresh stock race engineer into a package. Both write into the package prefab asset, so the change travels with the track.

Check the cast with Draftmaster›NPCs›Director (Ctrl+Shift+N): flip between Practice / Qualifying / Race and everyone greys out or lights up, with a reason per row ("not in Race", "wins is 0, needs 5..∞"). Install Default Pit Cast turns the runtime greeter / engineer / crew chief into editable markers.

Detail: Docs/NPCs-and-Quests.md §0

Design what an NPC looks like

GameObject›2D Object›Layered NPC (Paper Doll), then work in the inspector: per layer pick a style sheet and a colour, with live Scene-view preview. The preview layers are real children, so what you see is what builds at runtime.

There is clothing now. Until recently only the Base body sheet existed, so every clothing category was skipped at Build() and NPCs walked around as bare silhouettes. Assets/Sprites/Walking/Parts/ now holds 13 placeholder sheets — 2 bottoms, 2 shoes, 3 tops, 3 hairs, 3 hats — all 56×8 (7 frames of 8×8, matching walk_base.png), painted in the white/grey ramp so the runtime tint multiply colours them. They are crude on purpose; redraw them in place and nothing else changes.

Each layer owns a band of the body so nothing above it hides it completely: bottoms take the hips + feet rows, shoes the toe pixel at each end, tops the shoulders + arms rows, hair and hats the head block (same place on all seven frames, so they repeat one pose across the strip). Every part was cut from walk_base's own silhouette, so no part pixel lands off the body.

Adding a part: drop the PNG under Assets/Sprites/Walking/Parts/ with the import settings from the doc, add it to that category's Options in Assets/Resources/NPC/NPCPartLibrary.asset, then add swatches to its Tint Options — those are what the random crowd draws from. Colour variety is all tint: 5 skin, 8 shirt, 6 trouser, 5 shoe, 6 hair, 6 hat.

Sprite spec, the greyscale/tint rule and the band table: Docs/NPCs-and-Quests.md §1

Add crowd chatter

Draftmaster›NPCs›Dialogue Pool (Selected Track) creates or opens the per-track pool; Dialogue Pool (Global) the shared one; Seed Global Dialogue Pool From Built-Ins fills it from the hardcoded lines. A pool is claimed by its trackId field.

Add a side quest

  1. Assets›Create›Quests›Quest, saved into Assets/Resources/Quests/.
  2. Fill in objective type, target, reward (rewardItemId makes it a chain link), prerequisites.
  3. Put it on an NPC: QuestGiverNPC — setting quest on a PlacedNPC turns it into one — and fill the five line sets: offerLines, activeLines, turnInLines, completedLines, lockedLines.
  4. A delivery target is the same component with isDeliveryTarget on and offersQuest off.

Objective types, stat keys and the pause-menu mission board: Docs/NPCs-and-Quests.md §3

Add an app to the phone

The player's phone slides up from the bottom on foot (P) with six tile slots — Tasks, Notes, SoBuzz and DrivR fill four, and the spare bays are drawn empty so nothing reflows when a fifth arrives.

Adding one is a PhoneApp subclass plus a line in PhoneUI.BuildApps(). The base class carries the drawing vocabulary (Section, Row, Body, Meter, Plate); each helper returns the height it used, so Draw is a running y += and the total is what the device scrolls.

Writing to the existing apps from elsewhere: PhoneTasksApp.Push(id, text) and Resolve(id) for a reminder line, PhoneNotes.Record(...) for a log entry, PhoneUI.Open("drivr") to open straight into an app.

Edit drivers

Window›Draftmaster›Driver Database — edits the same SQLite file the game reads, so changes show up in Play Mode. To change the schema or the seeded roster, edit Assets/Scripts/Database/ and bump DatabaseManager.SchemaVersion to force a rebuild.

Which row is the player? PlayerDriver reads the persisted car number (career.carnumber, defaulting to #8 — the number RaceScene's PlayerCar is painted in) and hands it to RosterLookup.ByCarNumber: the Drivers table when the database is open, the code roster when it isn't, which is every menu scene in the editor. A career name overrides the name only. Look the player up by name and you get nothing, because no save sets one.

Adding a column to Driver? Declare the row once in DriverAttributeSheet — the garage builder lays rows out in that order and GarageScreenUI fills them by index, so a row can't end up labelled one thing and filled with another.

Dressing & art

Every generator here writes real, editable objects — then refuses to overwrite them.

Sponsors and car decals

  • Draftmaster›Sponsors›Create Car Sponsor Layout — the asset saying where the hood / tail / quarter panels sit on the livery.
  • Generate Placeholder Decals — one car-scale logo per brand in the database, so the feature is playable before any real art. Overwrite the PNGs later; nothing else changes.
  • Preview Slots On Livery writes Temp/SponsorSlotPreview.png; Preview Sponsored Car shows the baked result.

Docs/Sponsorship.md

Edit the RV, inside and out

Draftmaster›RV Interior›Build Prefab generates Resources/OnFoot/RVInterior.prefab once — after that it is yours: open it in Prefab Mode and lay it out, swap the placeholder squares for art. Build refuses to overwrite; Force Rebuild loses hand edits. Same pair for the exterior (Build RV Prefab).

Authoring frame: (0,0) is where the player spawns, +Y points at the doorway.

Edit the travel map

Draftmaster›Travel Map›Build Prefab once, then edit Resources/UI/TravelMap.prefab by hand. Sync Node Markers adds markers for nodes added to TravelGraph later without moving existing ones; Snap Markers To Graph Layout re-snaps everything to the code positions; Open (Play Mode) opens the map without the F9 key. Geography is code-defined in TravelGraph.

New world art (sprites, props)

The standard is 12.8 px/m. Import at that PPU — never fix size with transform scale.

  • Art›Retarget World Sprites to Pixel Standard — bulk-fix import PPU.
  • Audit Pixel Scale — writes Docs/PixelScaleAudit.md.
  • Report Sprite Scale Compensation — finds prefabs faking size with scale.
  • Apply Pixel Standard to Open Scene + Rebuild Track Generators after changing materials or tiling.
  • Report Surface Material Usage — who else uses a material before you retile it.

UI work

  • Kit setup: Art›Set Up Iron Oval Kit, then Verify Iron Oval Kit (writes Docs/IronOvalKit.md). Older kit: Set Up / Verify Pixel UI Kit.
  • Everything reads one asset: Assets/Resources/UI/PixelUITheme.asset.
  • Move authored Canvases onto the kit: Restyle Scene Canvas UI / Restyle UI Prefabs.
  • The IMGUI race panels are code (PixelGUI), not prefabs.
  • Screens from the design file: Build Title Screen Scene and Build Garage Screen Scene regenerate Assets/Scenes/TitleScreen.unity / GarageScreen.unity. The race HUD and results screen are code, not scenes — see below.
  • Scanlines run [ExecuteAlways]: IronOvalScanlines builds its own DontSave overlay canvas, so a screen is authored through the same TV line the player sees and the overlay never lands in the scene file.
  • Demo-flow prefabs: UI›Build Demo UI Prefabs — car setup panel + control hint.
  • Font trouble: Dump Pixel Font Atlas, Preview Dialogue Bubble.

Race HUD & results

IronOvalRaceHUD is the in-race readout from the design file: position and speed as big numerals with a hard shadow, lap count in gold under them, tyre/draft plate on the right. It self-installs at load — there is nothing to place in a scene.

It replaces three older readouts rather than sitting on top of them: the authored speedometer dial, the "P x / N" position panel and RaceDirector's own lap counter all stand down while it runs, so nothing draws twice. Turn its enabled off and they come back — that is the switch if you need the old dial for a comparison.

The results screen is the restyled RaceDirector.DrawResults, also code.

Gotchas

The ones that cost an hour before you remember them.

"Force Rebuild" items destroy hand edits. The plain Build … items refuse to overwrite on purpose.
Geometry-anchored NPCs need a track in the scene — preview a package, or author inside the package's own Prefab Mode stage.
The race scene has no road. Manager fields pointing at a TrackBuilder are filled at load (BindSceneReferences only fills nulls); serialise a road into the scene and no package can ever load.
Road courses are hand-authored. The oval generator refuses them.
Scenes and prefabs are binary-serialised. Text search won't find a GUID inside one — use the Unity MCP tools or the editor.
Editing the seeded roster or calendar needs DatabaseManager.SchemaVersion bumped, or the old table survives.
F6 drives three panels and F9 two — tyre wear, sponsor board and the UI-kit showcase all answer F6. Only F10–F12 are still free; a new panel should take one of those.
A title-screen row pointing at a scene that isn't in the build settings draws disabled, not broken. That's the design — but it means "my new menu row does nothing" is almost always a missing build-settings entry.
The race HUD stands the old readouts down. IronOvalRaceHUD self-installs and switches off the speedometer dial, the position panel and RaceDirector's lap counter so nothing draws twice. Missing dial = it's doing its job; disable the component to get them back.
The player is found by car number, not name. PlayerDriver → RosterLookup.ByCarNumber, defaulting to #8. A lookup by career name returns nothing, because no save sets one.
Play mode pauses while the editor is unfocused, so nothing driven by game time ticks while you work in another window.
